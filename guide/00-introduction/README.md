# 00 — Введение в dbt и analytics engineering

## Цель

Понять, что такое dbt, какую проблему он решает и где он находится в
современном стеке данных — прежде чем писать код.

## Теория

### ETL vs ELT

- **ETL** (Extract, Transform, Load): данные трансформируются *до*
  загрузки в хранилище. Трансформация происходит в отдельном движке
  (Spark, ETL-инструмент) и часто становится узким местом / чёрным ящиком.
- **ELT** (Extract, Load, Transform): данные сначала загружаются в
  хранилище как есть, а трансформация происходит *внутри* хранилища с
  помощью SQL. Именно под эту модель создавался dbt — дешёвые облачные
  хранилища (Postgres, Snowflake, BigQuery, Redshift, Databricks) сделали
  подход "просто выполняем больше SQL" реалистичным в масштабе.

### Что на самом деле делает dbt

dbt **не** извлекает и не загружает данные. Он предполагает, что сырые
данные уже есть в хранилище (загружены Fivetran, Airbyte, самописными
скриптами и т.д.), и даёт вам:

1. Способ писать **T** из ELT как версионируемые `SELECT`-запросы
   (модели), которые dbt сам компилирует в `CREATE TABLE/VIEW AS ...`.
2. **`ref()`/`source()`** — граф зависимостей (DAG) между моделями,
   который строится автоматически по тому, как модели ссылаются друг на
   друга, вместо ручного выстраивания порядка запуска.
3. **Тесты** — утверждения о данных (`not_null`, `unique`,
   `relationships`, кастомные бизнес-правила), которые выполняются как
   часть пайплайна, а не постфактум.
4. **Документацию** — описания и граф зависимостей, сгенерированные из
   того же проекта, поэтому они всегда синхронизированы с кодом — ведь
   они *часть* кода.
5. **Снапшоты** — историю изменений (SCD Type 2) для таблиц, которые в
   источнике просто перезаписываются.
6. **Макросы (Jinja)** — переиспользуемую SQL-логику, управляющие
   конструкции и возможность переопределять внутренние механизмы dbt.
7. **Пакеты** — способ переиспользовать чужие проверенные макросы
   (`dbt-utils`, `dbt-expectations` и т.д.).

### Где место dbt в стеке

```
   Извлечение и загрузка       Трансформация              Потребление
 (Fivetran/Airbyte/         (dbt: это руководство)    (BI-инструменты, ML,
  самописные скрипты)                                   reverse ETL)
        │                          │                        │
        ▼                          ▼                        ▼
  Сырые таблицы в    ───────►  staging → marts  ───────►  Дашборды,
     хранилище                (models/staging,             ноутбуки,
                                models/marts)               приложения
```

В dbt Labs эту дисциплину называют **analytics engineering**: применение
практик software engineering (система контроля версий, тестирование,
CI/CD, модульность, документация) к слою SQL-трансформаций, которые
раньше жили в невезионируемых, непроверенных, скопированных вручную
запросах внутри BI-инструментов.

### dbt Core vs dbt Cloud

Здесь используется **dbt Core** (open-source CLI), запущенный в Docker,
потому что это бесплатно, воспроизводимо и наглядно показывает каждую
команду — а именно это нужно, чтобы по-настоящему *понять* инструмент и
показать это понимание работодателю. dbt Cloud — коммерческая обвязка
(планировщик, IDE, хостинг документации) вокруг того же движка dbt Core;
всё, что вы освоите здесь, напрямую переносится и туда.
