# 01 — Настройка окружения

## Цель

Поднять весь стек через Docker и получить зелёный `dbt debug`.

## Теория

`docker-compose.yml` в репозитории описывает три сервиса:

| Сервис | Назначение | Доступ |
|---|---|---|
| `postgres` | "Хранилище данных" для проекта | `localhost:5432` (а также из контейнера `dbt` по имени хоста `postgres`) |
| `dbt` | Контейнер с установленными `dbt-core` + `dbt-postgres`, проект примонтирован в `/usr/app/dbt` | `docker compose exec dbt <команда>` |
| `adminer` | Лёгкий веб-интерфейс для просмотра базы Postgres | http://localhost:8080 |

Сам dbt не работает как демон — это CLI, который вызывается на каждую
команду (`dbt run`, `dbt test` и т.д.). Контейнер `dbt` просто остаётся
живым (`tail -f /dev/null`), чтобы можно было заходить в него сколько
угодно раз, не тратя время на пересоздание контейнера каждый раз.

Параметры подключения хранятся в двух местах, оба уже настроены:

- `docker-compose.yml` / `.env` — как **Docker** поднимает Postgres.
- `dbt_project/profiles/profiles.yml` — как **dbt** подключается к
  Postgres. Это обычный `profiles.yml` dbt, просто примонтированный из
  репозитория, а не лежащий в `~/.dbt/profiles.yml` на вашей машине.

## Практика

```bash
# из корня репозитория
cp .env.example .env      # один раз, при первом запуске
make up                   # docker compose up -d --build

# проверяем, что всё поднялось
docker compose ps
```

Теперь убедимся, что dbt действительно достаёт до Postgres:

```bash
make shell                # открывает bash внутри контейнера dbt
dbt debug                 # должно закончиться "All checks passed!"
exit
```

Или без захода в shell:

```bash
docker compose exec dbt dbt debug
```

Откройте (пока пустую) базу данных в браузере на
http://localhost:8080 — System: `PostgreSQL`, Server: `postgres`,
логин/пароль/база — из вашего `.env`.

### Полезные команды на будущее

```bash
make logs          # смотреть логи всех контейнеров
make psql          # psql-сессия прямо в базу проекта
make down          # остановить контейнеры (данные Postgres сохранятся в volume)
make clean         # остановить контейнеры И удалить volume с данными Postgres
```

Любую команду `dbt` в этом руководстве можно выполнить либо как
`docker compose exec dbt dbt <команда>`, либо, находясь внутри
`make shell`, просто `dbt <команда>`. Дальше в руководстве используется
короткая форма в предположении, что вы уже внутри контейнера — откройте
`make shell` и держите его открытым.

## Задание

1. Выполните `make up`, затем `make shell`, затем `dbt debug`. Устраните
   любой красный вывод, прежде чем идти дальше (самая частая причина —
   забыли `cp .env.example .env`).
2. Выполните `dbt --version` и отметьте установленные версии dbt-core /
   dbt-postgres.
3. Откройте Adminer и убедитесь, что можете войти и увидеть пустую базу
   `dbt_demo` (таблиц пока нет — это ожидаемо, мы ещё ничего не запускали).

## Чек-лист

- [ ] `docker compose ps` показывает запущенными `postgres`, `dbt` и `adminer`.
- [ ] `dbt debug` внутри контейнера dbt проходит все проверки.
- [ ] Я могу зайти в Adminer на http://localhost:8080.
- [ ] Я понимаю разницу между переменными окружения в `docker-compose.yml`
      и `profiles.yml` (сетевая настройка Docker vs подключение dbt к хранилищу).
