# 11 — Документация

## Цель

Сгенерировать и открыть сайт документации dbt для этого проекта и
добавить собственную документацию.

## Теория

dbt генерирует документацию целиком из метаданных проекта — отдельной
вики, которую нужно вручную поддерживать в актуальном состоянии, не
существует. Есть три источника:

1. **Поля `description:`** в `.yml`-файлах (см. `_core__models.yml`,
   `_jaffle_shop__models.yml`, `_events__sources.yml`) — короткие
   описания на уровне модели или колонки.
2. **Блоки `{% docs %}`** в `.md`-файлах (см.
   `_jaffle_shop__docs.md`) — для более длинных описаний, которые хочется
   переиспользовать или которым тесно в одной строке; на них ссылаются
   через `{{ doc("block_name") }}` внутри поля `description:`.
3. **Сам DAG** — каждая связь `ref()`/`source()` становится узлом и
   стрелкой в графе зависимостей автоматически, без дополнительной
   настройки.

`dbt docs generate` компилирует всё это (плюс метаданные из хранилища —
типы колонок и т.д.) в статический сайт; `dbt docs serve` поднимает его
локально.

## Практика

```bash
make shell
dbt docs generate
dbt docs serve --host 0.0.0.0 --port 8085
```

Или, с хост-машины, во втором терминале:

```bash
make docs
make docs-serve
```

Откройте **http://localhost:8085**. Изучите:
- **Граф зависимостей** (иконка справа внизу) для `fct_orders` —
  нажмите на неё и выберите "View Lineage Graph", чтобы увидеть цепочку
  `raw seeds → stg_* → fct_orders`.
- Откройте `stg_customers` и `stg_orders` в списке моделей — их описания
  берутся из `{{ doc("stg_customers") }}` / `{{ doc("stg_orders") }}`,
  которые резолвятся из `_jaffle_shop__docs.md`.
- Откройте source `raw.events` и убедитесь, что конфиг freshness тоже
  виден в документации.

## Задание

1. Добавьте блок `{% docs %}` для `stg_payments` в
   `_jaffle_shop__docs.md`, подключите его в `description` модели
   `stg_payments` в `_jaffle_shop__models.yml`, пересоздайте
   документацию и убедитесь, что он отображается.
2. В графе зависимостей для `dim_customers` проследите весь путь обратно
   до `raw_customers` и проговорите каждый переход вслух (как будто
   объясняете это интервьюеру, глядя на ваш экран).
3. Добавьте `meta:`-теги к `fct_orders` в `_core__models.yml` (например,
   `meta: {owner: "you", contains_pii: false}`) — они появляются в
   сгенерированной документации и доступны через `dbt ls --output json`
   — именно так команды строят собственные каталоги/дашборды владения
   данными поверх метаданных dbt.
